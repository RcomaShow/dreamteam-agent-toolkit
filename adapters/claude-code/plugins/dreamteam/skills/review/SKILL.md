# DreamTeam Review 0.5.0

Scope: `$ARGUMENTS`

1. Read the route decision, concrete agent role, execution chain, rejected candidate, pricing catalog, token forecast, DCP/2, CHP/2, anchors, checkpoints, charges, reservations, tool events, and invalidations.
2. Confirm the direct baseline is Sonnet-only and every active Lean, Opus-Sonnet, or Frontier stage is included exactly once. Lean delegation must include explicit root executive overhead unless the compatibility escape hatch was intentionally used.
3. Reject hidden Haiku usage in Opus-Sonnet and missing Opus/Sonnet usage in higher-tier topologies.
4. Confirm `execution-sonnet-lead` acts as the bounded implementer and that authored changes are accepted only by a different `verification-independent-reviewer` identity.
5. Validate the handoff with `dreamteam_protocol.py`, requiring run/task/contract binding and current anchors.
6. Confirm the author and independent reviewer are different agents and that C3/public-contract regions remain executive-owned.
7. Check reread ratio, immutable config hash, path policy, strict-mode invalidations, and reservation commit/release. Treat ledger charges as forecast/accounting values unless authoritative provider usage was explicitly reconciled.
8. Reject unsupported facts, hidden assumptions, unresolved handoffs, stale anchors, over-budget routes, false checks, or malformed records.
9. Inspect consequential hunks directly; sample mechanical hunks and use targeted checks rather than repeating discovery.
10. Keep cost, total-token, main-token, normalized-payload, and handoff metrics separate. A cheaper model is not by itself a token-saving result.
11. Cost/token publication claims require paired invariants, complete quality parity, configured margins, minimum samples, and positive lower-tail results in every reported bucket. Normalized payload claims require complete sidecar measurements.
12. Forecast routing must keep `empirical_claim_allowed=false` until representative paired provider results pass the claim gates.
13. Report `SCOPED`, `IMPLEMENTED`, `COMPILED`, `TESTED`, `REVIEWED`, and `VERIFIED` only when actually achieved.
